# Skytrace for macOS and iOS

A native SwiftUI flight tracker for macOS, iPhone, and iPad, with Apple Maps, an offline aircraft catalog, saved observations, and Airframes ACARS messages.

For iOS 17+ setup and signing, see [the iOS guide](iOS-setup.md). Open `Skytrace-iOS.xcodeproj` to run the mobile app. The macOS instructions below still apply to the desktop app.

## Build and run

The repository contains source code for macOS 14+ and iOS 17+. The app code is released under the [Unlicense](LICENSE). Third-party data and platform assets retain their own terms; see [third-party notices](THIRD_PARTY_NOTICES.md).

The aircraft database is downloaded locally and is not committed to this repository. Bootstrap it before running Swift package commands:

```sh
python3 scripts/update-catalog.py
swift test
./scripts/build-app.sh
```

Open the generated `../Skytrace.app` on macOS, or open `Skytrace-iOS.xcodeproj`, select the **Skytrace-iOS** scheme, and run on an iPhone/iPad simulator or a device with your signing team selected. The build helpers download the catalog automatically if it is missing. Python 3 is required for this initial download, not to run the app.

Builds generated by the macOS script are signed locally and are not Apple-notarized. Device iOS builds require your own signing setup; no signing credentials or provisioning profiles are included.

## Using Skytrace

- **Live radar:** shows recent positions from adsb.lol. Select an aircraft in the list or map to inspect its registration, type, altitude, speed, heading, and vertical rate. Choose a region from the menu, or enter custom coordinates in Settings. The radius is in nautical miles. Positions refresh every 10 seconds.
- **Aircraft database:** searches the downloaded aircraft catalog (623,216 records in the snapshot used during initial validation). Search matches the beginning of a registration, hex address, type, owner, or description. Results are paged 100 at a time. Column sorting applies to the current page.
- **Aircraft inspector:** contains an overview, locally saved track, flight history returned by Airframes, and up to 100 recent messages for that aircraft. Use the star to add or remove it from the watchlist. Use Reload to request updated details.
- **ACARS messages:** fetches up to 100 recent messages every 30 seconds and keeps the latest 1,000 in the view. Search by flight, registration, hex address, label, station, or text. Filter by datalink type. Select Historical search, choose a day, and press Search to query the provider archive. Load older messages at the end of the results. Export saves the currently filtered messages as CSV.
- **Tracking history:** lists up to 500 recently observed aircraft. The inspector shows up to 5,000 latest saved positions for a selected aircraft. Show track opens them on the radar; Export CSV saves them. A track connects observations at most two minutes apart; longer gaps and antimeridian crossings are left disconnected.
- **Watchlist:** saves aircraft locally. A watched aircraft has a live position only when it is present in the currently requested area and feed.

Refresh feeds with **Command-R**. Pause automatic refresh with **Command-Shift-P** or the radar pause button. Open Settings with **Command-comma**. Manual refresh still works while automatic refresh is paused.

## Airframes access

The public endpoints tested successfully without a key during development. Provider access rules and rate limits can change. If you receive an access error, obtain an API key from Airframes and save it in Settings. The key is stored in macOS Keychain and is only sent to the Airframes API. Test connection checks the key currently entered in the field; Save key applies it to the app.

The app polls the documented REST API. It does not subscribe to the Socket.IO firehose, and polling does not capture every message transmitted between refreshes. Airframes data is supplied by Airframes.io and its community of feeders.

## Database and history coverage

The catalog contains the complete downloaded upstream snapshot, including records with unknown or incomplete fields and known miscoded addresses. It is not a guaranteed registry of every aircraft worldwide. Build year, owner, and model appear only where the source supplies them.

There is no bundled worldwide lifetime history, ownership chain, maintenance history, or accident history. The app displays flights returned by Airframes and tracks collected locally while it is running. The Airframes airframe-detail endpoint currently returns a bounded list of flights, which may omit routes or dates. Historical ACARS availability depends on provider archives and account permissions. No history is fabricated to fill gaps.

Local data is in `~/Library/Application Support/Skytrace/history.sqlite`. Observations, messages, and the watchlist survive relaunches. The catalog is bundled separately and read-only. Retention defaults to 90 days; Settings offers 30, 90, or 365 days. Expired observations and messages are pruned at launch. The app does not continue recording when closed or while the Mac is asleep. Back up the data folder while the app is closed to preserve it.

## Source and builds

The repository contains the Swift package, Xcode iOS project, tests, artwork, and build scripts. The catalog is generated locally by the downloader. No external Swift dependencies are required. Build with a compatible Xcode/Swift toolchain on macOS:

```sh
python3 scripts/update-catalog.py
swift test
./scripts/build-app.sh
```

The script builds a release executable, copies its resource bundle into Skytrace.app, and signs the resulting app locally in a temporary staging folder. It produces both Skytrace.app and a ZIP archive; the ZIP avoids Finder metadata that cloud-synced folders can attach to application bundles. It builds for the host architecture. The project was built and tested on Apple silicon with Swift 6.4.2 / Xcode 27.2; other macOS/toolchain combinations have not been tested.

To refresh the offline catalog, use Python 3 and rebuild:

```sh
python3 scripts/update-catalog.py
./scripts/build-app.sh
```

The update script validates the record count before replacing the existing catalog and records its download date. It updates aircraft metadata, not historical flights.

## Validation

Twelve automated tests pass, covering feed parsing, missing/invalid records, provider hex-code normalization, authentication headers, rate-limit responses, real catalog queries, SQL wildcard escaping, observation deduplication, persistence, watchlist changes, and retention.

The packaged app was launched and checked with live ADS-B positions and Airframes messages. Catalog search, aircraft history, date-based ACARS search, watchlist add/remove, history across a restart, and a 100-message CSV export were checked in the running app. Exported CSV was parsed back successfully with consistent columns. Provider availability and map coverage remain external dependencies.
